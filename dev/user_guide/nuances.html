Nuances and known issues#

This page lists the places where cultivars behaves differently from what experience with other packages would suggest, and the defects known in the current pre-release. Every item says what to do instead and links to the page that demonstrates it.

The first part describes deliberate design that will stay. The second part, Known issues in 1.0.0a4, lists bugs and gaps found while writing this guide against 1.0.0a4; items leave the list as they are fixed, and the release notes record each fix.

By design#

Data and samples#

Column names are not read. VAR(df) labels its variables y1, y2, … even when df is a labelled dataframe. Pass names=tuple(df.columns). See Conventions.

Outputs cover the effective sample. resid, fittedvalues and every per-period decomposition start after the lags and differences, and the default to_pandas() index runs from 0 on that sample, not from the original positions. Drop the first p (or d) dates before attaching them. See Conventions.

Comparisons need a common sample. compare and likelihood_ratio_test raise DimensionError when two results have different nobs, as a VAR(1) and a VAR(2) on the same data do. Trim the data so both effective samples coincide. See Diagnostics and specification testing.

Missing values are refused, not dropped. Only the state-space engines accept gaps, and they differ in which pattern they accept: the linear Gaussian engine takes gaps in any element, the nonlinear and Kim engines only whole missing rows, the Hamilton filter none. See State-space models and filtering.

Results and what they offer#

Univariate results do not forecast. AR, ARMA/ARIMA/ SARIMA, the GARCH family, ARFIMA, SETAR, STAR and the Markov-switching AR return results with simulate but no forecast. Unobserved components forecast, returning (mean, std). SV has forecast_variance. To evaluate a univariate model out of sample, backtest it through the predict= hook; see Forecasting and forecast evaluation. Volatility models shows how to compute GARCH variance forecasts from the fitted recursion.

Bayesian VARs are not closed systems. BVAR, GibbsBVAR, StudentBVAR and BVARSV results have no ma_representation. The identification schemes, SpectralDensity, SpectralCausality and Spillover therefore refuse them. For a shrunk estimate that can still be identified, pass a prior to VAR (VAR(y, order=4, prior=MinnesotaPrior())). See Bayesian VARs and Architecture.

Identification is constructed, not requested. Write RecursiveSVAR(var, order=...).identify(). The method var.identify(scheme) exists on reduced-form results but does not work with the shipped schemes; see Known issues in 1.0.0a4.

Several result families are deliberately narrow. SparseVAR and GraphicalVAR results have no forecast or irf. The time-varying VARs have no forecast and, except TVPSVAR, no irf. MarkovSwitchingVAR has no forecast, simulate or irf. Architecture has the full capability matrix.

Summaries can be uneven. Box-Jenkins summaries state that standard errors are not yet available. The state-space filter records have no summary() and print as full dataclass reprs, so print the fields you need. The Johansen rank test and lag-order selection records use to_table() instead of summary().

Specification defaults#

``lag_order_selection()`` without ``max_lags`` can select absurd orders. The default scores every order the sample supports, and on short samples the criteria can then favour very long lags. Always pass max_lags. The method scores linear, unshrunk VARs even when called from a nonlinear or Bayesian model, and it refuses orders a wide system cannot fit by least squares. See Vector autoregressions and Bayesian VARs.

``n_draws`` means different things. It is the number of draws kept for BVAR and HierarchicalBVAR. For GibbsBVAR, StudentBVAR, BVARSV and FactorSV it is total iterations, which must exceed n_burn (500 for GibbsBVAR, 1000 for the others). Default thinning is 1 for GibbsBVAR and FactorSV and 2 for StudentBVAR and BVARSV. Read n_kept on the result. See Conventions.

Default seeds differ. Sign-restriction samplers default to seed=0. Posterior samplers and StochasticVolatilitySVAR default to None and are not reproducible unless you pass a seed.

Forecast horizons default differently. VARResult.forecast() defaults to one step; BVARResult.forecast() and forecast_paths() to eight. Pass steps explicitly.

``BVAR`` is conjugate. It refuses priors that break conjugacy, such as a Minnesota prior with cross_equation different from one. Use GibbsBVAR for the sampled posterior under that prior, or VAR(prior=...) for the shrunk point estimate. See Bayesian VARs.

Parameter counts differ by family. SETAR and STAR leave the innovation variance out of n_params; AR, VARs, threshold VARs and Markov-switching models include it. Information criteria are therefore offset by one parameter across those families. See Conventions.

Structural analysis#

“One standard deviation” depends on the scheme. Proxy and non-Gaussian schemes scale shocks to the full sample, heteroskedastic identification to the first regime, structural stochastic volatility to average volatility. Sign conventions differ too: recursive and long-run schemes make the diagonal positive, others make each column’s largest entry positive. Compare schemes on responses normalized to a unit impact. See Structural identification.

Unrestricted columns in a sign-restricted set have no fixed sign. A shock you did not restrict can enter the accepted set with either orientation, so its quantile bands mix both. Restrict at least one sign of every shock you intend to read.

A sign-restricted set can be smaller than requested. When the attempt budget runs out with some but not all draws accepted, the result holds fewer draws and no warning is raised. Check n_accepted and acceptance_rate on the result. When no draw is accepted the sampler raises SpecificationError. The remedies are to shorten the horizons, loosen a sign or raise max_attempts. SetIdentifiedSVAR signals an empty set with NumericalError instead.

Narrative events are indexed on the effective sample. Subtract the VAR order from the raw position of the event date. See Structural identification.

A VECM reports itself stable. VECMResult.is_stable is True although the system has unit roots by construction, so long-run and mixed schemes accept it at construction and refuse only at identify().

Forecast evaluation#

Point backtests have no quantiles. On a point forecaster, BacktestResult.quantile(tau) and the pinball loss return the point forecast for every tau. Use a density forecaster (forecast_paths) for quantile evaluation. See Forecasting and forecast evaluation.

Pass one series to comparison tests. ForecastComparison flattens its inputs. Passing losses() for all series at once, with shape (T, k), tests T * k interleaved values. Select one series with losses(..., name=...).

Frequency domain#

Phase signs differ by module. In SpectralDensity, a negative phase means the cause leads. In the wavelet results, a positive phase and lead mean the first series leads.

Band arguments are named differently. The band-pass filters take low/high, SpectralCausalityResult.band takes low_period/high_period, and the wavelet results take scale_band=(low, high). All are in periods. See Spectral analysis and filtering.
